# Одна текущая локальная кампания — 22 октября 2026

Приложение продолжает сохранённую в этом браузере игру. Облачное подключение, Firebase SDK и конфигурация, авторизация, каналы/комнаты, импорт и экспорт кампании удалены из интерфейса и исполняемого проекта. Старые настройки облака остаются неактивными данными; сетевые обращения и удаление удалённых данных не выполняются. Создание героя внутри текущей группы по-прежнему доступно.

## Порядок чтения и записи

1. `dndworld2:campaign-envelope` остаётся основным проверяемым сохранением. Версия схемы, checksum, revision/parentRevision, CAS, очередь и receipt не изменены. Адаптер выбирает самый новый проверенный envelope из доступных долговечных хранилищ; localStorage не обязательно содержит последнюю запись, если браузер использовал IndexedDB.
2. При отсутствии envelope загружается `dndworld2:world-snapshot`. Прежний снимок проходит существующую проверку и миграцию; исходные байты сначала записываются в `dndworld2:campaign-envelope:backup`.
3. При отсутствии снимка читаются прежние ключи `dndworld2:chars`, каталоги, `combat`, `fxround` и остальные поля. Ещё более старый `dndworld:chars` преобразуется по прежней схеме без добавления стартового героя.
4. Журнал остаётся отдельной записью `dndworld2:journal` с чтением `dndworld:journal` для прежнего формата. Общая атомарность мира и журнала не заявляется: сбой журнала сохраняет dirty-флаг и предупреждение при закрытии, но не откатывает уже подтверждённый мир.
5. Обычные последующие коммиты по-прежнему обновляют rolling backup предыдущим проверенным envelope и совместимые ключи. Произвольные старые пользовательские ключи и резервные записи не удаляются. Автосохранение и beforeunload-защита остаются активны.

## Исправления сохранности текущей игры

- Удалён startup `applyStructuredReleaseMigration`, который вызывал восстановление исходной группы и сброс незавершённого боя.
- `ensureTorgar/Septih/Legerem`, старые начальные экипировки и персональные аудиты выполняются только для нового хранилища. Уже сохранённый произвольный состав, включая пустой список, не пополняется стартовыми героями.
- Загрузка существующей партии больше не вызывает `pruneIncompleteCampaignArsenal`. Раньше неполное описание пользовательского предмета удаляло его из инвентаря, экипировки, торговцев и сундуков. Теперь запись сохраняется; проверка готовности механики остаётся обязательной перед исполнением действия.
- Непустой повреждённый старый список персонажей (ошибка JSON, `null`, объект вместо массива, пустая строка или некорректная запись внутри массива) останавливает загрузку до изменения каталогов и постановки автосохранения. Отсутствующий ключ означает первый запуск; сохранённый `[]` означает намеренно пустую группу.
- Текст системных сообщений сохранения обновлён. Имена, заметки и журнал пользователя не подвергаются текстовой замене.

## Приёмка и история

`tests/local-campaign-persistence.test.mjs` проверяет envelope, старый снимок и отдельные ключи без migration-маркеров: точный состав, текущие/временные HP, личный предмет, монеты, использованные кости здоровья, незавершённый бой с потраченным действием, раунд эффектов, журнал и повторную локальную загрузку. Отдельно проверены пустая группа, самый ранний формат и отсутствие активных cloud/import/export входов.

`npm run qa:local-persistence` работает в новом изолированном Chromium-контексте с синтетическим прежним сохранением. Он проверяет исходную сессию, отсутствие облачных запросов даже при старой включённой настройке, редактирование имени обычным полем, завершённую durable запись и реальную перезагрузку. Поддерживается `QA_SITE_ROOT`; проверка включена в Pages вместо прежнего импорта/экспорта.

Исторические файлы перечислены в [архиве отключённых функций](../archive/retired-cloud-2026-10-22/README.md), который не публикуется. Локальные проверки отката, очереди, CAS и действий не удалены. Непубликуемый offline inspector сохраняет чтение старых файлов для диагностики, без сетевого транспорта и без возможности подменить текущую игру.

Проверки используют синтетические данные. Они не подтверждают содержимое реального браузера владельца и не обращаются к удалённой базе. Полный общий gate и проверку собранного сайта выполняет ведущий агент перед публикацией.
