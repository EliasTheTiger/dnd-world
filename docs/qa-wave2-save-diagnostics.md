# QA перед игрой: диагностика сохранений, волна 2

Дата: 21 октября 2026. Область: только read-only `scripts/save-inspector.mjs`, его тесты и описание форматов. Runtime, облачная синхронизация, авторизация и исходные сохранения не изменены.

## Найдено и исправлено

1. **Envelope с подменённой или отсутствующей checksum объявлялся `ok`.** Добавлены async `inspectSaveVerified` / `inspectFileVerified`; CLI использует `persistence-core.verifyEnvelope`, включая проверку пары `revision`/`parentRevision` внутри envelope (`revision = parentRevision + 1`), transactionId, канонизацию и SHA-256. Статусы CLI: `verified`, `unverified`, `corrupt` плюс ошибки чтения/совместимости. Синхронные функции сохранены и больше не обещают проверенную целостность envelope.
2. **Повреждённые вложенные списки выбрасывали TypeError.** `inventory`, `spellbook`, `abilities`, `combat.order`, списки определений и каталогов проверяются до обхода. Невалидные записи, ID, виды участников и ревизии описываются в отчёте. Отсутствующие ссылки spellbook/abilities/combat также больше не пропускаются молча.
3. **Повреждённый JSON в legacy per-key превращался в пустой список.** Присутствующий некорректный ключ теперь делает отчёт `corrupt` с точным именем поля. Дополнительный legacy-ключ не может скрыть envelope или неизвестную будущую схему.
4. **Актуальная cloud-обёртка с `payload` не распознавалась.** Поддержаны она и старый формат `{by, at, j}`. Проверяется внутренний envelope; метаданные транспорта явно остаются неподтверждёнными.
5. **Префикс `bg3:` выглядел как доказательство существования определения.** Отчёт сохраняет каталоговые pins и внешние ID, но указывает `references.status: partial` и `catalogStatus: unverified`. Отсутствующий pin и конфликт версий диагностируются. Загружаемые каталоги не подменяются фиктивными локальными определениями.

## Границы гарантии

- `verified` означает согласованность envelope с его checksum; это не подпись автора, не подтверждение актуальности backup и не гарантия корректной игровой механики. История предыдущих envelopes не загружается и не проверяется.
- Ссылки проверяются в инвентаре, книге заклинаний, способностях персонажа и порядке боя. Вложенные ссылки всех возможных правил, экипировки, торговцев и сундуков этим инструментом не симулируются.
- Каталоги не скачиваются и не гидратируются. Даже pin с manifestSha256 остаётся сведением из сохранения, пока внешний каталог не проверен отдельно.
- CLI возвращает 0 для читаемых `verified`/`unverified`; интеграции должны дополнительно проверять `validationStatus` и `issues`.
