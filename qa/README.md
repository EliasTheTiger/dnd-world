# Итоговая интеграционная проверка

Подготовьте зависимости и Chromium один раз:

```powershell
npm install
npx playwright install chromium
```

Вся итоговая приемка запускается одной командой:

```powershell
npm run qa:integration
```

Команда последовательно запускает точный полный набор
`node --test tests/*.test.*` (включая 500 независимых сквозных кампаний), а
затем независимый browser smoke в новом профиле Chromium. В каждой кампании
реальные обработчики движка выполняют предмет, заклинание, способность,
экипировку, оружие и ответ противника; торговля, валюты, сундуки, добыча и
перезапуск репозитория проходят через соответствующие production-core модули.
Команда прекращает работу при первом ненулевом коде.

Оркестратор строго проверяет оба итоговых артефакта. В
`campaign-matrix.json` должны быть ровно 500 завершенных и поведенчески
различных конфигураций и по 500 production-коммитов каждого обязательного
типа. Поля evidence намеренно разделяют фактически исполненные определения
(`productionExecutedIds`), построенные и проверенные структурированные формулы
локального runtime (`structuredFormulaValidation`) и полный census допущенных
либо явно fail-closed определений (`catalogAdmissionCoverage`). Admission не
считается исполнением предмета, заклинания или способности. В `run.json` любой `FAIL`, `BLOCKED`,
console/page error, `requestfailed` или HTTP-ответ 4xx/5xx делает итоговый
прогон красным.

Browser smoke пользуется только видимым UI и DOM: он не читает `localStorage`,
IndexedDB, снимки мира или внутренние функции приложения. По умолчанию он сам
поднимает статический сервер для текущего checkout.

Артефакты каждого запуска получают уникальный идентификатор и сохраняются в
`qa/evidence/<run-id>/`: `campaign-matrix.json` и `run.json`. Для каждого
пользовательского сбоя сохраняются JSON, PNG и DOM-фрагмент.

Переменные специализированного browser runner:

- `QA_HEADLESS=0` или аргумент `--headed` — видимый Chromium.
- `PLAYWRIGHT_CHROMIUM_EXECUTABLE_PATH` — путь к полному Chromium, если в
  окружении установлен браузер, но отсутствует отдельный headless shell.
- `DND_WORLD_QA_URL` — опубликованная сборка вместо локального сервера.
- `QA_SITE_ROOT` — корень уже собранного сайта; CI указывает `_site`, монтирует
  его по `/dnd-world/` и тем самым проверяет тот же Pages-кандидат, который
  затем допускается к публикации.

`DND_WORLD_SKIP_FULL_SUITE=1` действует только вместе с `CI=true` в отдельном
CI-job, где полный Node-набор уже завершился в обязательном `test`-job. В
обычном локальном окружении этот флаг игнорируется, поэтому единая команда
всегда запускает полный набор.
