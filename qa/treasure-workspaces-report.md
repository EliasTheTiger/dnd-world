**Торговцы и сундуки: исправления от 7 сентября 2026 года**

Основная причина неудобства — смешение подготовки мастера и действий игрока на одном длинном экране. Большие списки технических идентификаторов скрывали названия предметов, стоимость сделки не показывалась заранее, а обновление всего экрана при изменении поля могло повторно вызвать обработчик потери фокуса. Проверки структуры HTML и многократное повторение простых операций не покрывали эти реальные сценарии.

Теперь у торговца четыре вкладки: торговля, ассортимент, настройки мастера и журнал. Форма создания показывает условия выбранной профессии и стартовую кассу. Для предметов добавлен поиск, для покупки и продажи — предварительный расчёт суммы и доступности. В журнале отображаются имена героев и предметов. Ручные цены задаются за штуку и применяются как окончательные.

Сундуки разделены на игру, содержимое и свойства. Открытие и получение добычи — отдельные действия. Мастер может выбрать получателя, выдать добычу из разрушенного сундука, явно открыть замок ключом, настроить характеристику спасброска и его последствия. В таблице добычи подписаны поля, показаны относительные вероятности и причины исключения предметов. Добавление строки сохраняет раскрытую таблицу. Ручное разрешение особой награды позволяет выйти за рекомендации генератора; неизвестные и дублирующиеся уникальные предметы остаются запрещены.

| Найденная ошибка | Что исправлено |
| --- | --- |
| Продажа проверяла первый экземпляр предмета, а списывала последний | Выбирается конкретная запись инвентаря; списывается именно проверенная запись |
| Продажа заполненной сумки могла оставить вещи без контейнера | Нужно сначала вынуть содержимое; неудачная сделка ничего не меняет |
| Проценты торговца могли применяться к уже сниженной цене продажи | Коэффициент применяется к каталожной стоимости один раз |
| Дробные коэффициенты терялись при отображении | Сохраняются и показываются сотые процента |
| Ручную цену невозможно было задать в ассортименте | Добавлены окончательные цены покупки и продажи, включая нулевую |
| Сюжетные ограничения проверялись только при создании/пополнении | Проверяются также при расчёте и проведении сделки |
| Пополнение пересекающихся категорий давало меньше стартового остатка | Восстанавливается сумма целевых количеств из всех правил |
| Откат устаревшей сделки мог стереть параллельную правку мастера | Версия проверяется до изменений; снимки для отката берутся непосредственно перед последствиями |
| Выданное содержимое можно было заново редактировать и утверждать | Защита действует в интерфейсе и в доменной модели, включая загрузку сохранения |
| Разрушение сундука делало добычу недоступной | Получение содержимого разрешено и из разрушенного контейнера |
| Генерация могла заменить фиксированную сюжетную награду | Фиксированная награда задаётся вручную |
| Уникальные предметы дублировались; нехватка вариантов молча уменьшала награду | Дубликаты отклоняются; нехватка разных вариантов объясняется мастеру |
| Денежная награда зависела от неиспользуемой таблицы предметов | Режим «Только монеты» не проверяет неучаствующие строки |
| Все теги предмета принимались за обязательное окружение | Ограничения окружения берутся из отдельных данных `lootContexts` |
| Каталоги выбора и проверки сундука могли различаться | Используется общий каталог доступных предметов |
| Ловушка шаблона не отключалась после нормализации | Явное отключение сохраняется |
| Ловушки всегда использовали Ловкость и половину урона | Характеристика и результат успешного спасброска настраиваются |
| Английский тип урона ловушки не совпадал с русским сопротивлением | Тип приводится к обозначениям боевого движка |
| Ловушки ложного сундука и контейнера с существом игнорировались | Открытие применяет и ловушку, и соответствующее событие контейнера |
| Мимика можно было уничтожить как предмет, сохранив полные хиты противника | Атаки мимика разрешаются боевым движком; фиктивные настройки замка/ловушки убраны |
| Отсутствующие результаты проверок превращались в провал | Без фактического ввода действие отклоняется до коммита |
| Вскрытие использовало навык Ловкость рук | Используется Ловкость и владение воровскими инструментами; наличие инструментов проверяется |
| Награда меняла монеты без версии кошелька и записи об операции | Точное целочисленное зачисление, новая версия и денежный журнал |
| Повторный `blur` вмешивался в замену DOM | Перерисовка защищена от повторного входа |
| Быстрый клик «Забрать добычу» после открытия отклонялся, пока ещё сохранялось первое действие | Действия заблокированы до завершения операции и подтверждённого сохранения; после успеха или ошибки обновляются снова |

Проверки:

- Повторная проверка выделенной версии: 1 259 тестов без ошибок (доменные матрицы, контракты UI, сценарные регрессии и сборка Pages), включая два быстрых действия во время незавершённого сохранения.
- Сборка Pages: две проверки пройдены; новый CSS копируется и получает адрес с версией релиза.
- `qa/treasure-workspaces.e2e.cjs` проверяет реальные элементы интерфейса: создание торговца, поиск, покупку/продажу, дробные цены, подготовку и выдачу награды, запрет повторной выдачи, отмену ловушки, спасбросок Телосложения без урона при успехе, таблицу, запись сохранения и ширину 390 px. Тест запускает неизменённое приложение со штатной инициализацией, затем подготавливает небольшой сценарный мир в отдельном браузерном контексте. Повторный сценарий с обычным запуском пройден.
- Снимки экрана и журналы находятся в `qa/evidence/merchant-chest/`.
- Сквозной сценарий `qa/player-agent.e2e.cjs` обновлён под новые вкладки: проверяет остатки на карточках, запрет покупки без денег, открытие без преждевременной выдачи, отдельное получение на следующем ходу и запрет повторной выдачи. Ловушку обезвреживает Септих с воровскими инструментами. Все проверки выполняются через видимый интерфейс. Семь контрактных тестов сценария проходят.
- Предыдущий полный прогон общей рабочей копии выявил 14 ошибок в соседних изменениях. Исправления этого отчёта выделены в отдельную ветку; для неё повторно запущен `node --test tests/*.test.*`. Профильные проверки не заменяют обязательный полный прогон и строгий интеграционный этап публикации.
